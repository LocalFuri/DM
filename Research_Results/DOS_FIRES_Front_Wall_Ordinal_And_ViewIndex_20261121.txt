Dungeon Master PC DOS — Front-wall ordinal and F2 view-index identification
Date: 2026-11-21
Scope: Original user-supplied ReDMCSB DUNVIEW.C and DEFS.H, unpacked original FIRES code and previous live DOSBox-X observations. READ ONLY. No Unity or DOS game modification.

1. IMPORTANT CORRECTION TO PRIOR RESEARCH
The high-three-bit dispatch in live function 114C:1408 is a dungeon SQUARE-TYPE dispatch, not a set of seven ornament categories. Group 0 is WALL. The wall branch prepares several face-oriented ornament ordinals. Previous descriptions of all offsets +06/+08/+0A/+0C as equivalent wall ornaments omitted that the first is the BACK face in this branch.

2. ORIGINAL DEFS.H SOURCE, BRANCH X720_I34E_I34M_P31J
The square-aspect record has seven 16-bit entries (14 bytes):
+00 word index 0 = C0_ELEMENT (square type)
+02 word index 1 = C1_SQUARE (square data)
+04 word index 2 = M550_FIRST_THING
+06 word index 3 = C3_BACK_WALL_ORNAMENT_ORDINAL
+08 word index 4 = M551_RIGHT_WALL_ORNAMENT_ORDINAL
+0A word index 5 = M552_FRONT_WALL_ORNAMENT_ORDINAL
+0C word index 6 = M553_LEFT_WALL_ORNAMENT_ORDINAL

3. VERIFIED LIVE CALLER MAPPING
The caller function 2A64:33ED reserves 0Eh local bytes beginning at [BP-0E]. The first ornament argument pushed at 2A64:3474 as [BP-04] is local record offset +0A: the FRONT-WALL ORNAMENT ORDINAL. It is NOT the native GRAPHICS.DAT image index. The second argument is the VIEW WALL INDEX.

The original DUNVIEW.C F0107 declaration names the two parameters P0116_i_WallOrnamentOrdinal and P0117_i_ViewWallIndex. It explicitly checks whether ordinal is zero and returns immediately. For a nonzero ordinal it subtracts one before indexing G0101_as_CurrentMapWallOrnamentsInfo and selecting its native bitmap index and coordinate set. Thus ordinal zero = absent wall ornament. A nonzero ordinal is a per-map one-based identifier, not the global type index.

4. VIEW INDEX (15-ENTRY BRANCH) — KEY NEW FINDING

0 = D3L2_RIGHT
1 = D3R2_LEFT

Live calls seen earlier with second arguments 0008 and 000B are D2R_LEFT and D2R_FRONT, respectively. They do NOT identify the center F2 front wall. For the Hook at CENTER F2, the target view index is decimal 10, hexadecimal 000A. Thus the observed 0008/000B calls with first argument zero can naturally refer to empty noncentral wall faces.

This is a source-defined index correspondence, not a proof of which tile the player is facing. Verify player position, view, and map square before expecting a nonzero Hook ordinal.
