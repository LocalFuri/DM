2. Algorithm pipeline from DUNVIEW.C, COORD.C and DEFS.H
A. Dungeon square data and direction select the appropriate wall-face ornament ORDINAL. Ordinal zero means absent ornament. Current-map ornament index = ordinal minus one (DUNVIEW.C F0107 around lines 1711-1717). This is NOT a native image index.
B. Per-map wall-ornament info supplies NativeBitmapIndex and CoordinateSet (DUNVIEW.C around lines 1716-1725). The 15-entry graphics/layout branch computes ZoneIndex = 1004 + CoordinateSet*15 + ViewWallIndex.
C. The chosen view index determines front/side bitmap selection, horizontal mirroring, ordinary F2/F3 scale, and special extreme-side D3 behavior (DUNVIEW.C around lines 1828-1884). Ordinary D2 uses 21/32; D3 uses 14/32. Extreme D3 outer side views use horizontal 30, vertical 14 with special palette rules. D1 uses native bitmap.
D. F0675_DUNGEONVIEW_GetScaledBitmap reads M100_PIXEL_WIDTH / M101_PIXEL_HEIGHT from the NATIVE bitmap, caches/creates scaled bitmap and passes it to F0129_VIDEO_BlitShrinkWithPaletteChanges. DEFS.H macro M078_SCALED_DIMENSION = ((dimension*scale)+(scale>>1))>>5. Distinguish padded/native bitmap bounds from the opaque pixel bounds.
E. F0791_DUNGEONVIEW_DrawBitmapXX passes actual bitmap dimensions plus the layout zone into F0635_ in COORD.C. F0635_ follows layout records and parent regions, performs alignment and clipping. Final blit is F0132_VIDEO_Blit. This is the appropriate shared code to port; do not infer sprite positions solely from an un-clipped center formula.
F. Resource 696 in GRAPHICS.DAT is the 15-entry branch layout resource and was previously decoded into 23 ranges and 1,133 records. A correct implementation must parse resource 696, not hardcode Hook/Manacles positions.

3. Specific evidence already established through actual runtime and disassembly
- Unpacked FIRES function load-image offset 0x1D886 corresponds to the F0107 wall-ornament renderer, with independently inspected compiled instructions for 15-entry index / +1004, scale 21/14, and calls to bitmap/scaling/drawing helpers.

- Observed center-front D2/F2 view index is 000A per source-defined 15-entry view table; this is a target index, not proof the game was rendering Hook then.
- Hook/Manacles candidate dimensions and rectangles from prior research remain PREDICTIONS until each native bitmap mapping, actual view selection, clipping, and the engine build are checked on an actual draw. Do not silently elevate them to measured DOS values.

4. Key conclusion
These inputs together document a GENERIC, DATA-DRIVEN rendering pipeline. Original FIRES corroborates the reconstructed branch, while GRAPHICS.DAT supplies sprites and layout records and DUNGEON.DAT supplies ornament placements. The evidence argues for implementing the shared algorithm once, not for instruction-by-instruction manual tracing of 180 ornaments.
