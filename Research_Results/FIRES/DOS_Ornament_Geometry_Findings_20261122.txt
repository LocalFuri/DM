Generic DOS rules being tested
- Perspective zone = 1004 + coordinateSet*15 + DI.
- Destination dimensions = ((source_dimension*scale)+(scale>>1)) >> 5.
- 6-bit sampling step = floor(source_dimension*64/destination_dimension).
- Source sample = floor((dest_index*step + floor(step/2))/64).
- Centered rectangle left/top = center - ((dimension+1)>>1).
- Source brown colors (146,73,0)/(109,36,0) compared to DOS output brown (109,36,0).

Conclusion
The SAME generic 6-bit sampling rules and resource 696 placement rules predict all
28 brown pixels in both screenshots, with no brown-pixel classification errors.
The previously apparent S3 3x5 visible bound is NOT the scaling destination rectangle.
No additional Hook-specific placement/rounding patch is justified by these tests.

Limits
- DI=7 and DI=2 are uniquely well-supported by geometry/pixel comparison but are
  not measured live register values in FIRES. The source-to-bitmap index mapping
  also remains to be independently verified against the running engine.
- Brown-color classification is exact for these screenshots; this DOES NOT verify
  all palette entries, transparent pixels, black pixels, or all clipping paths.
- Only set 0 / left-side Hook views tested; do not generalize approval to other
  ornament types and views without further regression tests.
- No edits to Unity have been made in this package.
