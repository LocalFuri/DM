NEW SOURCE FINDING
ScummVM now has a complete C++ implementation of the shrink-with-palette operation, unlike the older snapshot that had DUMMY CODE. It rounds destination width to an even value, sets a fixed-point step:
    stepX = floor(32768*srcWidth/dstWidth)
    stepY = floor(32768*srcHeight/dstHeight)
Then samples source at:
    srcX = floor(dstX*stepX/32768)
    srcY = floor(dstY*stepY/32768)
It maps the sampled palette index through the palette remap (in its representation, palette entries are multiplied by 10). This is a CURRENT SCUMMVM REIMPLEMENTATION, not proof of original compiled DOS F0129 behavior.

Key diagnosis: fixed-point edge sampling is NOT the same as exact-fraction edge sampling for this 92->60,52->34 reduction. It selects the preceding source X at destination columns 15,30,45 and the preceding source Y at destination row 17, owing to truncation of the fixed-point step.

CONCLUSION
The ScummVM C++ routine is a valuable documented, testable generic baseline, but it does not match the original DOS Manacles F2 brown-pixel mask. None of these three candidates is accepted as the original DOS shrink algorithm; neither color-class F1 nor visual preference is proof. Need original DOS machine-code F0129 or exact output from its intermediate scaled bitmap, then all-index pixel comparison. Existing source-derived geometry and clipping remain separate issues. No ornament-specific workarounds. No Unity modifications.
